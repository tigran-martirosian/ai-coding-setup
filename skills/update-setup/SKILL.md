# Update the setup

The update is one script; your part is to run it, deal with the few things it can't do alone, and say what changed. It only writes the setup's own files. Skills, hooks, settings and notes the user added themselves are never touched, one of the setup's files that the user changed stays as they have it, and every file it replaces is kept next to the new one as `<name>.before-install-<date>`.

Small releases (only hook, skill, agent or worker files) install themselves: the update-check hook runs `update.mjs --files-only` in the background, and `~/.claude/update-check.json` `auto` holds the last one (version, time, ok or its error). A failed self-install is fixed by a normal run of this skill. Its `kept` lists the files the user changed, which it left as theirs: if they ask for the new version of them, run the script with `--replace <name>` for each (or `--replace-all`), as in step 3.

1. **Run it** (it also updates Claude Code itself and prints the version of the Claude Code that Nimbalyst ships; pass on a line starting `Nimbalyst runs its own Claude Code` or `Nimbalyst's Claude Code: now yours` as it is (new Nimbalyst chats then run the person's own Claude Code), and if it stops saying Claude Code is too old or could not update itself while it is running, give that message as it is and stop): `node ~/.claude/skills/update-setup/update.mjs` (allow up to 10 minutes: a changed extension is rebuilt). If it prints `Already on the newest version`, say so in one line, make the offers of steps 2 and 2b when there are any, then stop. If it prints `Update stopped:`, give the reason as it is and stop; nothing was changed.
2. **Rules.** Pass the `rules:` line on in one sentence (the setup's rules are always this version's; rules the person added are moved to `~/.claude/rules/my-rules.md`, which loads in every chat too, and the line names its undo). For each `notes: brought <folder>/CLAUDE.md up to this version` line, say in one sentence that the project folder's notes are this version's again and the rules the person had added there were moved to the `my-rules.md` the line names, in that folder's `.claude/rules`. Then run `node ~/.claude/skills/update-setup/own-rules.mjs --status --homes`; only if a file says `changed since last tidy`, run the same script with `--offered` (so the next prompt's reminder doesn't offer it twice) and make one offer on the question card (`AskUserQuestion`; in Nimbalyst `mcp__nimbalyst__AskUserQuestion`), yes (recommended) / not now, with the lines of all its files and about bytes ÷ 4 tokens: `Your own rules: <n> lines, about <t> tokens in every chat. Tidy them? Lines the setup already covers or does better go to a vault you can restore from; your own preferences stay. One command undoes it.` On yes: read `~/.claude/skills/update-setup/tidy.md` and follow it. On not now: `node ~/.claude/skills/update-setup/own-rules.mjs --skip --homes`. No question per rule. If the person says they don't need a setup rule ("I don't need the rule about design work"), run `node ~/.claude/skills/update-setup/update.mjs --leave-out "<the rule's bold opening, else its first six words>"`, with no form; `--put-back "<same>"` brings it back.
2b. **Disk and files.** Pass each `disk:` line on as it is (`disk: freed …` is the setup cleaning its own leftovers). The person decides on their own leftovers and on the file reorganize, on one question card (`AskUserQuestion`; in Nimbalyst `mcp__nimbalyst__AskUserQuestion`), with one question for each line starting `offer:` (from disk-tidy) and one for a `files-offer:` line; no such lines, no card. Each question in plain words, with the numbers its line gives:
   - own leftovers: `Your own leftovers: about <size> (<what>). Look through them now? About 2 minutes; nothing goes without your yes per item.` Options `Look through them now (recommended)` / `Not now`;
   - the chat archive (an `offer: Chats older than …` line): the line's own words, `Yes (recommended)` / `Not now`;
   - files: `<n> files in <m> project folders could be renamed or moved to the setup's layout, about <x> minutes. Every change is shown first and one command undoes it.` Options `Reorganize now (recommended)` / `Not now`.

   On yes: after the rest of the update, run `/disk-tidy` (leftovers, chat archive) or `/file-upkeep` (files). On not now: for files run `node ~/.claude/skills/file-upkeep/file-check.mjs --skip --homes` (the next update then asks only about new findings); then one line, `Any time: /disk-tidy` or `Any time: /file-upkeep`.
3. **Files they changed.** Only if the output has the line `Kept as yours`: the files listed under it are the setup's, but the user changed them (or had their own under that name), so they were not replaced and are now behind this version. Show the list and ask once: take this version's copy of all of them, of some (which ones), or keep theirs. A dated copy of theirs is kept either way. All: `node ~/.claude/skills/update-setup/update.mjs --replace-all`. Some: the same command with `--replace <name>` for each, the name as the list has it.
4. **Extensions.** The installer rebuilds a changed Nimbalyst extension itself: `extension installed: <name>` means it is in place, `extension unchanged` that nothing was needed. For a line `extension failed: <name> (...)`, give the reason and try once by hand in the folder the `extension changed:` line names: `npm install`, `npm run build`, `npm run install-ext` (`ink-themes` without `npm install`).
5. **Plugins.** `plugin installed:` and `plugin already there:` need nothing. For a line `plugin failed`, `skill failed` or `plugins not installed`, give the reason it names; the next update tries again. If `~/.telegram-control/secrets.json` exists, the phone bot is set up: run `node ~/.claude/skills/phone-bot/setup.mjs --restart` after the update so the running bot uses the new code. If it answers that the bot was not set up with `/phone-bot`, nothing is needed.
6. **Language.** The language question is asked only once. If the output has the line `Language: not chosen`, ask in a form with one singleSelect, English or Русский. Then run `node ~/.claude/skills/update-setup/update.mjs --language <english|russian>`, and call the Nimbalyst tool `mcp__nimbalyst-host__ai_set_preferred_language` with `ru` for Русский or an empty string for English (when that tool is available). `/update-setup russian` or `/update-setup english` changes the language at any time, with no question: run the same command with that language. After a change, say that Nimbalyst needs one restart for the buttons and that new chats answer in that language, and write the reply in the chosen language.
7. **Model.** Only if the output has a line starting `MODEL CHANGED`: an install from before 1.0.74 that had `"model": "sonnet"` and no effort setting was moved to Opus at medium effort. Do not ask; say it in the reply, with the line's own words, and give the undo the line prints. `/update-setup --keep-model` runs `node ~/.claude/skills/update-setup/update.mjs --keep-model`, which puts `sonnet` back and keeps it on every later update. A line `model: sonnet is back` says that was done.
7b. **Ink look.** Only if the output has a line starting `theme: set now:` (Nimbalyst is open, so the installer could not write it). Call `mcp__nimbalyst-host__appearance_set_theme` with `com.local.inktheme:ink-cobalt`. Only if that call succeeds, run `node ~/.claude/skills/update-setup/update.mjs --theme-done`. If it fails, or the same output has `extension installed: ink-themes`, do not run it: tell the person to quit and reopen Nimbalyst and run `/update-setup` again. Without the tool: Theme button at the bottom of the left bar, Ink themes, Ink Cobalt. A line `theme: set to Ink Cobalt` means it is written; Nimbalyst shows it once it is reopened. This happens once; a pick made afterwards stays.
8. **Nothing else.** An update changes files only. Open no project folder or window, and ask about nothing the first install covered (the look of the editor, dictation, the default model): the user has those as they want them. Ask only the questions in steps 2, 2b, 3 and 6.
9. **Reply**, short, in the language the user writes in (the chosen language after a language change):
   - the version it is on now and the `What is new` line the script printed;
   - what the run listed at its end: the files it replaced, any retired skill it removed (one line each), any hook in the settings whose script is not there (name it, change nothing), and the file under `~/.claude/setup-logs` that has the whole run;
   - **the "Yours, on old versions" list**, whenever the run printed it: every file the user changed or had of their own, each with its `--replace` line exactly as printed (the same flag on `update.mjs` does the same, as in step 3). These stay behind this version until they take it; say so once, and that their own copy is kept either way. Say it even when they already answered the question in step 3 with "keep";
   - **start a new chat** for the next task: rules load when a chat starts. If an extension was installed: quit Nimbalyst and open it again;
   - anything that failed, with its output;
   - one offer: in a project they work in, `/setup-audit scan` checks and tidies that project's own `CLAUDE.md` and `DECISIONS.md` against the updated setup.

Budget: about 10 tool calls.

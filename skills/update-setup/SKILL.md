# Update the setup

The update is one script; your part is to run it, deal with the few things it can't do alone, and say what changed. It only writes the setup's own files. Skills, hooks, settings and notes the user added themselves are never touched, one of the setup's files that the user changed stays as they have it, and every file it replaces is kept, as it was, in `~/.claude/setup-logs/<YYYY-MM-DD>-install-backup/` under its path from the home folder (never next to the file). Copies an older version left next to a file as `<name>.before-install-<date>` move there on the first update.

Small releases (only hook, skill, agent or worker files, or a new Nimbalyst version the setup checked) install themselves: the update-check hook runs `update.mjs --files-only` in the background, and `~/.claude/update-check.json` `auto` holds the last one (version, time, ok or its error). A failed self-install is fixed by a normal run of this skill. Its `kept` lists the files the user changed, which it left as theirs: if they ask for the new version of them, run the script with `--replace <name>` for each (or `--replace-all`), as in step 3.

1. **Run it:** `node ~/.claude/skills/update-setup/update.mjs` (allow up to 10 minutes: a changed extension is rebuilt). It also updates Claude Code itself and prints the version of the Claude Code that Nimbalyst ships; pass on a line starting `Nimbalyst runs its own Claude Code` or `Nimbalyst's Claude Code: now yours` as it is (new Nimbalyst chats then run the person's own Claude Code). Stop, giving the message as it is, when it says Claude Code is too old or could not update itself while running, or prints `Update stopped:` (nothing was changed). If it prints `Already on the newest version`, say so in one line, make the offers of steps 2 and 2b when there are any, do step 10, then stop.
2. **Rules.** Pass the `rules:` line on in one sentence (the setup's rules are always this version's; rules the person added are moved to `~/.claude/rules/my-rules.md`, which loads in every chat too, and the line names its undo). For each `notes: brought <folder>/CLAUDE.md up to this version` line, say in one sentence that the project folder's notes are this version's again and the rules the person had added there were moved to the `my-rules.md` the line names, in that folder's `.claude/rules`. Then run `node ~/.claude/skills/update-setup/own-rules.mjs --status --homes`; only if a file says `changed since last tidy`, run the same script with `--offered` (so the next prompt's reminder doesn't offer it twice) and make one offer on the question card (`AskUserQuestion`; in Nimbalyst `mcp__nimbalyst__AskUserQuestion`), yes (recommended) / not now, with the lines of all its files and about bytes ÷ 4 tokens: `Your own rules: <n> lines, about <t> tokens in every chat. Tidy them? Lines the setup already covers or does better go to a vault you can restore from; your own preferences stay. One command undoes it.` On yes: read `~/.claude/skills/update-setup/tidy.md` and follow it. On not now: `node ~/.claude/skills/update-setup/own-rules.mjs --skip --homes`. No question per rule. If the person says they don't need a setup rule ("I don't need the rule about design work"), run `node ~/.claude/skills/update-setup/update.mjs --leave-out "<the rule's bold opening, else its first six words>"`, with no form; `--put-back "<same>"` brings it back.
2b. **Disk, files and backup.** Pass each `disk:` line on as it is (`disk: freed …` is the setup cleaning its own leftovers). The person decides on their own leftovers, on the file reorganize and, once, on the backup, on one question card (`AskUserQuestion`; in Nimbalyst `mcp__nimbalyst__AskUserQuestion`), with one question for each line starting `offer:` (from disk-tidy), one for a `files-offer:` line and one for a `Backup: not asked` line; no such lines, no card. Each question in plain words, with the numbers its line gives:
   - own leftovers: `Your own leftovers: about <size> (<what>). Look through them now? About 2 minutes; nothing goes without your yes per item.` Options `Look through them now (recommended)` / `Not now`;
   - the chat archive (an `offer: Chats older than …` line): the line's own words, `Yes (recommended)` / `Not now`;
   - files: `<n> files in <m> project folders could be renamed or moved to the setup's layout, about <x> minutes. Every change is shown first and one command undoes it.` Options `Reorganize now (recommended)` / `Not now`;
   - backup (a `Backup: not asked` line; no option is marked recommended, not everybody needs it): `Back up your Claude setup to the cloud, encrypted? Your settings, rules, skills, memory and any project folders you pick are copied to your own Backblaze B2 storage on the schedule you pick (daily, weekly or only when you ask); it is free up to 10 GB, then about $7 per TB a month. They are locked on this computer with a password only you keep, so Backblaze or anyone with the storage key sees only scrambled data. Setup takes about 10 minutes: you make a Backblaze account and keep one password.` Options `Yes, set it up` / `No (we won't ask again; /backup sets it up any time)`;
   - project folders (a `project-pass: level <old> → <new>, <n> folders behind` line): `<n> project folders you worked in lately were set up before this setup. When you next work in one, offer to bring it up to date, so sessions there get the current rules, systems map and file layout (about 15 minutes each, every change shown first)?` Options `Yes, when I open each (recommended)` / `Now, starting with <newest folder>` (the first `behind` line of `node ~/.claude/skills/update-project/pass.mjs --list`) / `No, don't offer`.

   On yes: after the rest of the update, run `/disk-tidy` (leftovers, chat archive) or `/file-upkeep` (files). On not now: for files run `node ~/.claude/skills/file-upkeep/file-check.mjs --skip --homes` (the next update then asks only about new findings); then one line, `Any time: /disk-tidy` or `Any time: /file-upkeep`. Backup: yes: `node ~/.claude/skills/update-setup/update.mjs --backup yes` (it puts the yes on record, so the next update doesn't ask again), then, after the rest of the update, run `/backup`; no: `node ~/.claude/skills/update-setup/update.mjs --backup no` (it only puts the answer on record), then `Any time: /backup`. Any other `Backup:` line (setup not finished, last run failed, last good run days ago) gets no card: pass it on in the reply as it is. Project folders: yes needs nothing run (the offer comes in each folder); now: after the rest of the update, `/update-project` on that folder by its path, with no window opened; no: `node ~/.claude/skills/update-project/pass.mjs --skip-all`, then `Any time: /update-project in a project folder`.
3. **Files they changed.** Only if the output has the line `Kept as yours`: the files listed under it are the setup's, but the user changed them (or had their own under that name), so they were not replaced and are now behind this version. Show the list and ask once: take this version's copy of all of them, of some (which ones), or keep theirs. A copy of theirs is kept in `~/.claude/setup-logs/<YYYY-MM-DD>-install-backup/` either way. All: `node ~/.claude/skills/update-setup/update.mjs --replace-all`. Some: the same command with `--replace <name>` for each, the name as the list has it.
4. **Extensions.** The installer rebuilds a changed Nimbalyst extension itself: `extension installed: <name>` means it is in place, `extension unchanged` that nothing was needed. For a line `extension failed: <name> (...)`, give the reason and try once by hand in the folder the `extension changed:` line names: `npm install`, `npm run build`, `npm run install-ext` (`ink-themes` without `npm install`).
5. **Plugins.** `plugin installed:` and `plugin already there:` need nothing. For a line `plugin failed`, `skill failed` or `plugins not installed`, give the reason it names; the next update tries again. If `~/.telegram-control/secrets.json` exists, the phone bot is set up: run `node ~/.claude/skills/phone-bot/setup.mjs --restart` after the update so the running bot uses the new code. If it answers that the bot was not set up with `/phone-bot`, nothing is needed.
6. **Language.** The language question is asked only once. If the output has the line `Language: not chosen`, ask in a form with one singleSelect, English or Русский. Then run `node ~/.claude/skills/update-setup/update.mjs --language <english|russian>`, and call the Nimbalyst tool `mcp__nimbalyst-host__ai_set_preferred_language` with `ru` for Русский or an empty string for English (when that tool is available). `/update-setup russian` or `/update-setup english` changes the language at any time, with no question: run the same command with that language. After a change, say that Nimbalyst needs one restart for the buttons and that new chats answer in that language, and write the reply in the chosen language.
7. **Model.** Only if the output has a line starting `MODEL CHANGED`: an install from before 1.0.74 that had `"model": "sonnet"` and no effort setting was moved to Opus at medium effort. Do not ask; say it in the reply, with the line's own words, and give the undo the line prints. `/update-setup --keep-model` runs `node ~/.claude/skills/update-setup/update.mjs --keep-model`, which puts `sonnet` back and keeps it on every later update. A line `model: sonnet is back` says that was done. A line `MODEL CHANGED in quick-tasks` says that folder moved from Sonnet to Opus once; its undo is `/update-setup --keep-home-model`, which leaves the global model alone.
7b. **Ink look.** Only if the output has a line starting `theme: set now:` (Nimbalyst is open, so the installer could not write it). Call `mcp__nimbalyst-host__appearance_set_theme` with `com.local.inktheme:ink-cobalt`. Only if that call succeeds, run `node ~/.claude/skills/update-setup/update.mjs --theme-done`. If it fails, or the same output has `extension installed: ink-themes`, do not run it: tell the person to quit and reopen Nimbalyst and run `/update-setup` again. Without the tool: Theme button at the bottom of the left bar, Ink themes, Ink Cobalt. A line `theme: set to Ink Cobalt` means it is written; Nimbalyst shows it once it is reopened. This happens once; a pick made afterwards stays.
8. **Nothing else.** An update changes files only. Open no project folder or window, and ask about nothing the first install covered (the look of the editor, dictation, the default model): the user has those as they want them. Ask only the questions in steps 2, 2b (the backup question among them, asked once while no answer is on record), 3 and 6, and the restart card of step 10.
9. **Reply**, short, in the language the user writes in (the chosen language after a language change):
   - the version it is on now and the `What is new` line the script printed;
   - what the run listed at its end: the files it replaced, any retired skill it removed (one line each), any hook in the settings whose script is not there (name it, change nothing), and the file under `~/.claude/setup-logs` that has the whole run;
   - **the "Yours, on old versions" list**, whenever the run printed it: every file the user changed or had of their own, each with its `--replace` line exactly as printed (the same flag on `update.mjs` does the same, as in step 3). These stay behind this version until they take it; say so once, and that their own copy is kept either way. Say it even when they already answered the question in step 3 with "keep";
   - **start a new chat** for the next task: rules load when a chat starts. If an extension was installed: quit Nimbalyst and open it again;
   - anything that failed, with its output, and a `Backup:` line other than `Backup: not asked`, as it is;
   - one offer: in a project they work in, `/update-project` brings it up to this setup;
   - the `nimbalyst:` line of step 10, in one plain sentence.
10. **Nimbalyst, last.** The setup delivers Nimbalyst: the version it checked, with its fixes, and Nimbalyst's own updater off. If the `nimbalyst:` line says `getting <version>`, run `node ~/.claude/tools/nimbalyst-patch/deliver.mjs --wait`, then the same command with `--status`, and use that line instead. Any other line is only passed on (step 9), unless it says `restart to finish: …` or `<version> installs when Nimbalyst closes`: then, after the reply, end with one question card (`AskUserQuestion`; in Nimbalyst `mcp__nimbalyst__AskUserQuestion`), options `Restart now` / `Later`:
    - `restart to finish` (the running Nimbalyst has no fixes yet, so it can't be closed for the update): `Restart Nimbalyst now to finish? After you pick Restart now, quit Nimbalyst once from its tray icon (right-click, Quit); the update and its fixes go in and it opens again in about a minute. Chats that are working right now stop, this one too.`
    - `installs when Nimbalyst closes`: `Restart Nimbalyst now to finish? It closes, the update and its fixes go in, and it opens again in about a minute. Chats that are working right now stop, this one too.`

    On Restart now: say in one line that Nimbalyst restarts now, then run `node ~/.claude/tools/nimbalyst-patch/restart.mjs` as the very last call (it carries on by itself when this chat stops). On Later: one line, that it goes in the next time Nimbalyst is quit, or for `restart to finish` that the next `/update-setup` asks again. If the person wants Nimbalyst to update itself again: `node ~/.claude/tools/nimbalyst-patch/deliver.mjs --off` (it puts the original app files back, at once if Nimbalyst is closed, otherwise when it next closes; `--on` undoes it).

Budget: about 10 tool calls.
